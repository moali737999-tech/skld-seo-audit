Technical SEO

50 / 100
What works
  • robots.txt is valid, allows all crawling, and correctly references the sitemap
  • sitemap.xml is valid, lists all 40 URLs with correct per-URL hreflang alternates (en/ar/x-default)
  • HTTPS enforced; http:// 301-redirects to https://
  • Fast TTFB (~337ms) and Brotli compression at the edge (Hostinger hcdn)
  • Canonical tag correctly self-references the non-www host even when loaded via www
Critical

Soft-404s: invalid URLs return HTTP 200 with homepage content

Requesting a nonexistent path returns HTTP 200 and renders the full homepage — the SPA router falls back to home instead of a not-found route. No noindex or 404 status is sent.

curl -s -o /dev/null -w "%{http_code}" https://skldeg.com/this-page-does-not-exist-xyz123200 ← rendered content = full homepage, no 404, no noindex
Fix → Render a real "not found" view for unmatched routes and return HTTP 404 (or 410) at the server. Add noindex on that view as a backstop.
High

www and non-www both serve 200 without a redirect

www.skldeg.com returns 200 OK directly instead of 301-redirecting to the non-www host. The canonical tag correctly points to skldeg.com, but this relies on every crawler and social platform respecting rel=canonical rather than one URL being enforced by the server.

curl -sI https://www.skldeg.com/HTTP/1.1 200 OK ← no Location header, no redirect
Fix → Add a 301 redirect from www to the canonical non-www host (or the reverse) at the hosting/CDN layer.
High

Missing standard security headers

The only security-relevant header present is a bare CSP directive. Strict-Transport-Security, X-Content-Type-Options, X-Frame-Options, Referrer-Policy and Permissions-Policy are all absent.

curl -sI https://skldeg.com/content-security-policy: upgrade-insecure-requests Server: hcdn ← no HSTS · no X-Content-Type-Options · no X-Frame-Options · no Referrer-Policy
Fix → Add HSTS, X-Content-Type-Options: nosniff, frame-ancestors 'self', and Referrer-Policy at the CDN/hosting layer.
Critical

All per-page metadata depends on client-side JavaScript

The raw HTTP response for every route tested — including individual blog posts — is an identical ~2.6KB app shell with the generic fallback title and no description tag at all. Unique per-page values only appear once a headless browser executes the JS.

curl -s https://skldeg.com/blog/top-seo-agency-dubai | wc -c2655 bytes ← raw HTML is the generic app shell, not the article
Fix → Move to server-side rendering or prerendering for at least the <head> metadata, so title/description/canonical/OG tags exist in the initial HTML for every route.

Content Quality

What works

  • Blog articles carry complete, valid Article schema: headline, author, dates, publisher, image
  • Full bilingual EN/AR coverage with correct lang="ar" dir="rtl" on Arabic pages
Critical

Meta description renders as the literal text "undefined"

Confirmed on 4 of 4 blog posts checked. This is what appears as the snippet in Google search results and in Facebook / LinkedIn / WhatsApp / Twitter link previews for every article.

grep meta[name=description] — /blog/top-seo-agency-dubai<meta name="description" content="undefined"> <meta property="og:description" content="undefined"> <meta name="twitter:description" content="undefined">
Fix → Trace the template variable binding — the post's description field is being read before it's populated, or the wrong field name is referenced. Re-check all published posts once fixed.
High

Content/URL language mismatch on /ecommerce

/ecommerce is hreflang-tagged as the English variant (Arabic counterpart at /ar/نمو-المتاجر), yet its own H1 and full body copy are written entirely in Arabic.

parsed h1 — https://skldeg.com/ecommerce (hreflang="en")"زوار بالآلاف وما فيمبيعات؟ متجرك لا يحتاج مجرد وكالة تسويق... بل يحتاج شريك استراتيجي"
Fix → Serve genuine English content on /ecommerce to match its hreflang="en" designation, or correct the hreflang/URL mapping.
Low

Possible slug / topic mismatch on a blog post

/blog/social-media-trends-2025 renders with the H1 "What Is Content Creation in Digital Marketing in Egypt?" rather than a social-media-trends topic implied by its slug.

Fix → Verify the slug matches the intended topic; correct if unintentional.

Schema & Structured Data

50 / 100
What works
  • Valid Organization schema (name, url, logo) present sitewide
  • Blog posts carry complete Article schema — headline, image, dates, author, publisher, mainEntityOfPage
Medium

Organization schema is minimal and missing local/contact signals

Only name, url and logo are present — no sameAs (social profiles), no address, telephone or ContactPoint, and no LocalBusiness/ProfessionalService typing despite SKLD serving a specific Egypt/UAE market.

Organization schema — every page{ "@type": "Organization", "name": "SKLD", "url": "https://skldeg.com/", "logo": "..." }
Fix → Add sameAs social links, a ContactPoint, and address/LocalBusiness data.
Medium

No BreadcrumbList, Service, or FAQPage schema

Services, Case Studies and Blog pages have a clear hierarchy (Home > Services, Home > Case Studies > Client, Home > Blog > Post) but no BreadcrumbList schema was found anywhere, and no Service schema exists on the Services page.

Fix → Add BreadcrumbList to hierarchical templates and Service entries per offering on the Services page.

AI Search Readiness

40 / 100
What works
  • Substantial blog content (1,000+ words) gives AI answer engines real passages to cite
  • Article schema's named author is a concrete E-E-A-T signal
High

Broken and duplicated descriptions undermine AI-citation summaries

AI answer engines (Google AI Overviews, Perplexity, ChatGPT search) commonly draw on the title/description pair as a first-pass summary. With that field duplicated across pages or literally "undefined," every page sends the same or a broken summary signal.

Fix → Resolving the Critical title/description bugs above is the single highest-leverage AI-readiness fix.
Medium

No llms.txt; content requires JS to appear

No llms.txt file was found, and because meaningful content only appears after JavaScript executes, any AI crawler that doesn't fully render JS sees only the generic app shell.

Fix → SSR/prerendering (already recommended under Technical SEO) is the structural fix; an llms.txt is a smaller optional addition.
